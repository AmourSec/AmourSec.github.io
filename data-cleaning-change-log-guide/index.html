数据清理为什么要保留 Change Log

一个说明 CSV/表格清理为什么要保留 change log 的指南，覆盖 row_id、field、old_value、new_value、reason、confidence、needs_review 和人工复核边界。

清理完的数据表本身只能说明“结果是什么”，不能说明“哪些地方被改过、为什么改、是否需要人工确认”。

如果表格后面还要给同事、客户、编辑或自己复查，change log 比“清理得很整齐”更重要。它让每一次修改都有来源、有理由、有边界。

Change Log 为什么重要

1. 可复核

清理表格时，格式统一、拼写修正、分类映射、重复记录判断经常混在一起。如果没有记录，复核者只能重新猜一遍。

change log 可以把“确定的机械修正”和“需要判断的变更”分开。

2. 建立信任

别人接收清理后的数据时，最关心的通常不是表格有多漂亮，而是有没有误删、误合并、误推断。

一份变更记录可以说明：

  • 哪些字段只是格式标准化。
  • 哪些字段来自明确规则。
  • 哪些字段只是推测，必须人工确认。
  • 哪些行没有被自动处理。

3. 方便回滚

如果某条规则后来被证明不合适，例如把 Web design 统一成 Website Design，但团队实际需要保留原始分类，change log 可以帮助定位受影响的行。

4. 保护责任边界

AI 或脚本适合做格式化、候选标记和重复检查，不适合悄悄替人决定身份、合同、付款、医疗、法律或客户记录的真实性。

保留 change log 可以把“工具做了什么”和“人需要确认什么”分清楚。

推荐字段

字段 作用 示例
row_id 指向原始数据中的稳定行号或唯一 ID R-003
field 被修改或标记的字段名 event_date
old_value 原始值 5/2/26
new_value 清理后的值；如果未自动修改，可留空或写 unchanged 2026-05-02
reason 修改原因或标记原因 Converted date to ISO format
confidence 置信度，建议用 high、medium、low high
needs_review 是否需要人工复核 false

也可以按项目需要增加：

字段 什么时候有用
rule_id 有一套明确清理规则时，用来连接规则清单
source_note 原始表格里有备注、来源或上下文时，用来说明依据
reviewer_decision 人工复核后记录接受、拒绝或改成其他值

虚拟示例

下面是完全虚构、非敏感的小表格，用来说明 change log 的形态。

原始表格：

row_id name event_date category fee
R-001 Lin Studio 2026/05/01 web design $300
R-002 Lin studio 2026-05-01 Website Design 300
R-003 Mira Notes 5/2/26 writing USD 120
R-004 Chen Lab next Friday data cleanup

清理后表格：

row_id name event_date category fee review_status
R-001 Lin Studio 2026-05-01 Website Design 300.00 ok
R-002 Lin studio 2026-05-01 Website Design 300.00 needs_review
R-003 Mira Notes 2026-05-02 Writing 120.00 ok
R-004 Chen Lab next Friday Data Cleanup needs_review

对应 change log：

row_id field old_value new_value reason confidence needs_review
R-001 event_date 2026/05/01 2026-05-01 Converted date to ISO format high false
R-001 category web design Website Design Applied category capitalization rule high false
R-001 fee $300 300.00 Removed currency symbol and normalized numeric format high false
R-002 row_id R-002 R-002 Possible duplicate of R-001 because name, date, category and fee are very similar medium true
R-003 event_date 5/2/26 2026-05-02 Parsed as May 2, 2026 based on stated date format rule medium true
R-003 category writing Writing Applied category capitalization rule high false
R-003 fee USD 120 120.00 Removed currency label and normalized numeric format high false
R-004 event_date next Friday next Friday Relative date cannot be resolved without source context low true
R-004 category data cleanup Data Cleanup Applied category capitalization rule high false
R-004 fee Missing amount, left blank for reviewer high true

注意这里没有自动合并 R-001 和 R-002。它们可能是重复记录，也可能是同一客户的两笔记录，必须由人确认。

不要静默修改或删除什么

以下情况应该标记 needs_review: true，而不是悄悄改掉或删掉：

  • 疑似重复行：只标记候选重复，不自动合并。
  • 姓名、公司名、账号名的等价判断：大小写、空格、缩写可能有业务含义。
  • 需要从上下文推断的日期：例如 next Friday、last week、Q2 kickoff。
  • 缺失的关键字段：例如金额、联系人、交付状态、原始来源。
  • 异常值：例如极高金额、负数、超出常见范围的日期。
  • 不在规则清单里的分类：只做候选映射，不替人决定。
  • 自由文本备注：备注里可能包含解释、例外或不适合机器改写的信息。
  • 涉及隐私、支付、医疗、法律、合同、身份或受监管数据的行：应停止自动处理，先脱敏、缩小范围或改用合规流程。

一个实用原则是：格式可以自动统一，事实不能自动发明，模糊判断不能自动当成事实。
