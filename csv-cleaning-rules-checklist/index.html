小型 CSV 清理前要先定义哪些规则

一个小型非敏感 CSV 清理前的规则检查清单，覆盖字段定义、必填项、格式、重复、缺失值、分类、异常值、变更记录和人工复核。

清理 CSV 之前，先不要急着让 AI “帮我整理一下”。

如果没有先定义字段和规则，AI 很容易把看起来相似的记录合并、把不确定的日期改成确定日期、把异常值当成错误删除。更稳妥的做法是：先写清楚数据目的、字段含义、允许的格式、哪些地方只能标记不能删除。

这个页面只适合小型、非敏感数据。不要把真实客户资料、订单、支付、医疗、身份证件、账号密钥、公司内部资料或受监管数据贴给 AI。

为什么需要字段定义和变更记录

CSV 清理常见问题不是“看不懂表格”，而是“改完之后不知道改了什么”。

字段定义能回答：

  • 每一列是什么意思？
  • 哪些列必须有值？
  • 日期、金额、分类应该是什么格式？
  • 哪些值可以自动标准化？
  • 哪些值只能标记给人复核？

变更记录能回答：

  • 哪些行被改过？
  • 改了哪个字段？
  • 原始值是什么？
  • 新值是什么？
  • 为什么改？
  • 是否需要人工确认？

没有这两样，清理结果很难复核。

清理前检查清单

项目 要定义什么 示例
数据目的 这份表要回答什么问题 统计虚构活动报名状态
字段列表 每一列的含义 name 是显示名称，不作为身份判断
必填字段 哪些字段缺失就要标记 event_date、category 必填
日期格式 统一格式 YYYY-MM-DD
数字格式 去掉货币符号、千分位或保留原样 1,200 -> 1200
分类值 允许的类别清单 workshop、talk、meetup
重复规则 什么算疑似重复 同邮箱或同电话只能标记，不能自动合并
缺失值 缺失时怎么处理 留空并标记 needs_review
异常值 超出范围时怎么处理 标记，不删除
手工复核 哪些行必须人工看 疑似重复、推断日期、缺失必填字段
变更记录 输出哪些列 row_id、field、old_value、new_value、reason

虚构示例

清理前

row_id name event_date category fee
1 Alex Chen 5/21 workshop NT$800
2 alex chen 2026-05-21 Workshop 800
3 Mei 五月二十二日 talk free
4 Lin 2026/5/23 meetup 1,200

规则

字段 规则
event_date 能明确判断时转成 YYYY-MM-DD；中文日期必须标记复核
category 转成小写，只允许 workshop、talk、meetup
fee 数字转成整数；free 转成 0 并记录原因
name 只清理前后空格，不自动判断身份重复
疑似重复 Alex Chen 和 alex chen 标记为疑似重复，不合并

清理后

row_id name event_date category fee status note
1 Alex Chen 2026-05-21 workshop 800 needs_review 与 row 2 疑似重复
2 alex chen 2026-05-21 workshop 800 needs_review 与 row 1 疑似重复
3 Mei 2026-05-22 talk 0 needs_review 中文日期和 free 费用需确认
4 Lin 2026-05-23 meetup 1200 ok 金额格式已标准化

变更记录

row_id field old_value new_value reason needs_review
1 event_date 5/21 2026-05-21 按上下文补全年份 yes
1 fee NT$800 800 去掉货币符号 no
2 category Workshop workshop 分类统一小写 no
3 event_date 五月二十二日 2026-05-22 中文日期转换 yes
3 fee free 0 免费值转数字 yes
4 fee 1,200 1200 去掉千分位 no

什么时候不要继续

如果 CSV 里出现这些内容，先停止：

  • 真实姓名、电话、邮箱和地址组合。
  • 订单号、付款记录、银行卡、发票。
  • 医疗、法律、财务、身份文件。
  • 公司内部客户表、员工表、合同或工单。
  • API key、Token、Cookie、账号密码。

这类数据需要先走脱敏和合规流程，不适合直接丢给 AI 工具。
