支持请求 Intake 模板

一个用于提交小范围问题的复制粘贴 intake 模板，帮助读者说明目标、上下文、链接、环境、已尝试步骤、预期结果和边界。

这个页面用于把小范围问题说清楚。

它不会自动发送邮件，不会创建工单，不会承诺回复，也不代表已经形成付费服务或交付关系。你可以复制下面的模板，整理好上下文后，再决定是否通过 支持与合作 页面提到的方式联系。

如果不想手工排版，也可以使用 支持请求格式化器 在浏览器本地生成同样结构的文本。它不发送、不保存。

如果已经收到读者请求，可以用 支持请求分流与回复草稿 判断应自助、补充信息、小范围查看，还是婉拒。回复草稿只能人工复核后手动发送。

适合谁

  • 有一个小范围技术问题，例如 Hexo / GitHub Pages 构建、主题配置、部署异常。
  • 想整理一段 Codex / AI Agent 工作流，明确输入、步骤和产出。
  • 想把一段文章草稿改得更清楚，但不需要事实核查或专业背书。
  • 想整理一个小型、非敏感 CSV / 表格的字段和清理规则。
  • 想使用 Codex Workflow Template Pack 里的模板，但不确定该填哪些信息。

不适合谁

  • 生产事故、紧急恢复、线上系统抢修。
  • 含有隐私、密钥、客户资料、订单、身份证件、支付信息、公司内部资料或受监管数据的问题。
  • 正式咨询、开发外包、安全审计、漏洞报告、法律、税务、财务、医疗建议。
  • 需要结果保证、响应时限、长期支持、保密协议或合同的任务。
  • 垃圾外链、刷量、虚假评价、绕过风控、账号代注册、爬取隐私数据或灰产需求。

边界说明

发送请求不保证回复，不保证会产生付费工作，也不表示已经接受委托。任何进一步处理都需要双方明确确认范围、材料、边界和是否适合继续。

如果请求中包含敏感数据、违法灰产、绕过平台规则、正式安全审计、生产事故、法律税务财务医疗等高风险内容，应该直接停止，不适合通过这个博客处理。
