Hexo 报错整理器增加复制结果按钮

记录 Hexo 报错信息整理器新增复制整理结果按钮的本地改进，说明它如何减少求助前的复制成本，并保持不上传、不保存日志。

这次小改动给 Hexo 报错信息整理器 增加了“复制整理结果”按钮和状态提示。

它仍然是一个纯前端静态工具：日志只在浏览器里处理，不上传、不保存、不发送。

为什么这个按钮值得做

整理器原本已经能把 Hexo 构建或部署日志转换成一份排查清单，但用户还需要手动选中输出区域再复制。这个步骤看起来很小，却会影响自助流程：

  • 用户可能只复制到一部分内容。
  • 用户可能忘记检查敏感信息。
  • 移动端手动选择长文本更麻烦。
  • 后续发给 Codex 或支持请求时，格式容易丢。

复制按钮的目标不是“自动提交”，而是让用户更容易把本地生成的清单带到下一步。

这次改了什么

  • 在整理结果旁增加 复制整理结果 按钮。
  • 生成清单后显示本地状态提示。
  • 没有可复制结果时提醒先生成清单。
  • 剪贴板 API 成功时提示已复制。
  • 浏览器阻止自动复制时，自动选中结果并提示手动复制。
  • 清空时恢复“不上传、不保存”的说明。

边界不变

  • 不上传日志。
  • 不保存内容。
  • 不发送请求。
  • 不接入后端。
  • 不新增依赖。
  • 不自动提交支持请求。
  • 不承诺能修复 Hexo 问题。

用户复制后仍然需要自己检查内容，尤其是私钥、token、cookie、邮箱、私有仓库、内部路径和客户信息。

和支持路径的关系

这个按钮让自助路径更顺：

  1. 在 Hexo 报错信息整理器 粘贴已脱敏日志。
  2. 生成结构化排查清单。
  3. 点击复制结果。
  4. 如果需要进一步整理字段，可以用 支持请求格式化器。
  5. 如果准备联系站长，再参考 支持请求 Intake 模板。

这仍然不代表已经形成付费服务或交付承诺，只是把读者自助整理问题的成本降一点。

后续补充

已在整理结果下方增加“下一步”链接组，指向支持请求格式化器、Intake 模板和支持页。这个区块明确说明：复制结果不等于提交请求、创建工单或形成服务关系，日志仍只在浏览器本地处理。
