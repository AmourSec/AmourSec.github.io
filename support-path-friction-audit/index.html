支持路径转化摩擦检查

检查从 Hexo 报错整理器到支持请求格式化器、Intake 模板和支持页的自助路径摩擦，列出本地可实施的小改动和边界。

这个页面检查一个具体路径：读者遇到 Hexo 报错后，能不能从工具整理问题，顺利走到支持请求材料，再决定是否联系或打赏。

这里不接入 analytics，不加外部追踪，不做邮件自动化，不创建表单，不改付款方式。目标只是找出本地页面可以改的小摩擦。

读者路径

一个有 Hexo 报错的读者，理想路径是：

  1. 进入 Hexo 报错信息整理器。
  2. 看到“不上传、不保存、不联网”和敏感信息提醒。
  3. 粘贴已脱敏的 Hexo 构建或部署日志。
  4. 点击“生成排查清单”。
  5. 点击“复制整理结果”。
  6. 如果需要补字段，进入 支持请求格式化器。
  7. 如果想看完整人工请求结构，进入 支持请求 Intake 模板。
  8. 如果仍需要联系或自愿支持，进入 支持与合作。

这条路径的重点不是强推联系，而是先让读者自助整理到“可以判断是否适合继续”的程度。

边界检查

页面 no upload / no save no formal service guarantee 备注
Hexo 报错信息整理器 明确写了不上传、不保存、不联网 写了只做信息整理，不自动判断根因 可以补“下一步链接组”
支持请求格式化器 明确写了不发送、不保存、不联网 写了不保证回复、不代表接受委托 可以补“来自 Hexo 整理器的结果放哪里”
支持请求 Intake 模板 写明不会自动发送、不会创建工单 写明不承诺回复或形成服务关系 可以补“工具用户快速路径”
支持与合作 不涉及工具输入 明确打赏不附带交付承诺 可以补“联系前材料清单”

推荐小改动

优先级按本地可实施、风险低、对读者路径帮助直接排序。

优先级 小改动 原因
1 在 Hexo 报错信息整理器 输出区下方增加“下一步”链接组 读者刚生成结果时最需要知道下一步
2 在 支持请求格式化器 增加一句说明：Hexo 整理器结果可以粘贴到“实际结果”或“上下文”字段 减少工具之间的断层
3 在 支持与合作 增加联系前最小材料清单 减少不完整邮件和误解

暂不做什么

  • 不接入 analytics。
  • 不做外部 tracking。
  • 不创建联系表单。
  • 不自动发送邮件。
  • 不保存读者日志。
  • 不改收款码或付款方式。
  • 不自动判断是否应该联系站长。

这些都涉及隐私、账号、数据收集或服务承诺，必须由用户单独确认。

下一步建议

下一轮优先实施第 1 项：在 Hexo 报错信息整理器 生成结果附近补一个本地“下一步”区块，链接到 支持请求格式化器、支持请求 Intake 模板 和 支持与合作。

这个改动不需要外部账号，不收集数据，不改变付款，也能直接降低读者从工具到支持路径的摩擦。
