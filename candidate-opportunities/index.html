外部候选机会任务表

把外部机会观察清单拆成 9 个可继续跟踪的候选来源，明确下一步检查项、本地可准备材料、需要用户批准的动作和适配风险。

这个页面把 外部机会观察清单 拆成更具体的候选来源。

这里只做观察和材料准备，不注册账号、不领取任务、不提交作品、不发送私信、不处理付款或提现。

使用原则

  1. 先看公开规则、任务质量和平台边界。
  2. 只做本地可验证材料：方案草稿、产品文案、截图清单、README、演示页。
  3. 任何账号、提交、发布、联系、收款、KYC、钱包地址或平台绑定，都需要用户明确批准。
  4. 不碰灰产、刷量、虚假评价、绕过风控、隐私数据和安全攻击类需求。

AI Agent / 赏金候选

候选来源 下一步检查什么 本地可先准备什么 需要批准什么 适配判断
Agent Bounty 看活跃赏金的分类、截止日期、交付格式、评分规则和是否允许 AI Agent 参与 为 1 个低风险任务写“需求拆解 + 方案大纲 + 风险清单”，不提交 注册、领取、提交成果、绑定收款方式 任务主题贴近 AI Agent，但赏金竞争和交付标准可能较高，先观察最小任务
MoltyBounty 看免费/付费 bounty 的可见内容、是否必须 Gmail 登录、是否涉及 USDC 钱包和 agent API 写一份“任务接受前检查表”：交付是否清楚、是否需要外部凭证、是否涉及隐私或付款 登录、claim 任务、提交、钱包地址、收款/提现 更像 agent 原生市场，但支付和身份边界更敏感，不能自动参与
IssueHunt 找文档、配置、测试补充类 issue，避开安全漏洞和复杂核心代码 为一个公开 issue 准备复现笔记、修复思路和 PR 说明草稿 GitHub 登录、认领/评论、提交 PR、领取 bounty 公开开源流程更成熟，但必须尊重维护者规则，不能无沟通抢修

当前优先级

优先级 候选 理由 最小可验证动作
1 模板 / 数字产品市场 已经有模板样品和目录结构，最容易继续本地完善 先写一版“上架文案草稿”，覆盖标题、卖点、FAQ、免责声明

先推进数字产品方向，因为它最符合“本地准备、低成本、可复用”的原则。
