Hexo Front Matter / YAML 报错排查清单

一个面向 Hexo 文章 Front Matter 和 YAML 报错的排查清单，覆盖 title、date、tags、categories、description、冒号、引号和缩进问题。

Hexo 的很多构建失败，不是主题坏了，也不是 GitHub Pages 坏了，而是某篇 Markdown 文章开头的 Front Matter 写坏了。

Front Matter 是 Markdown 文件顶部两条 --- 之间的元数据。Hexo 会先读取这里的 title、date、tags、categories、description 等字段，再决定怎么生成页面。一旦这里的 YAML 语法不合法，Hexo 可能在真正渲染正文前就失败。

注意几点：

  • --- 必须成对出现。
  • 字段名后面的冒号使用英文半角 :。
  • 冒号后面通常需要一个空格。
  • 列表项缩进保持一致。
  • 包含特殊字符的标题或描述，必要时加引号。

检查清单

检查项 常见错误 建议
title 标题里有冒号但没有引号，例如 title: Fix: Hexo error 改成 title: "Fix: Hexo error"
date 日期格式缺字段、用中文标点、或写成无法解析的自然语言 使用 YYYY-MM-DD HH:mm:ss
tags 混用单行数组和缩进列表，或缩进不一致 优先使用多行列表，每项两个空格缩进
categories 写成对象或缩进层级不一致 单分类用列表即可
description 描述里有冒号、引号、换行但没有处理 简短描述；含冒号时加引号
冒号 使用中文冒号 ： 或冒号后没有空格 使用英文 :，冒号后加空格
引号 引号不成对，或中英文引号混用 使用英文双引号并成对闭合
缩进 tab 和空格混用，列表缩进不一致 用空格，不用 tab
分隔线 只有开头 ---，没有结尾 --- 确保 Front Matter 前后都有分隔线
空值 tags: 后面什么都没有，但主题或插件期待数组 删除空字段，或补成规范列表

最小排查步骤

  1. 看报错里是否出现 YAMLException、front matter、source/_posts 或具体 Markdown 文件名。
  2. 找到最近新增或修改的 source/_posts/*.md 或 source/**/index.md。
  3. 只复制顶部两条 --- 之间的 Front Matter，先不要贴正文。
  4. 检查 title、date、tags、categories、description。
  5. 如果不确定，先把复杂标题和描述加英文双引号。
  6. 统一缩进，列表项使用两个空格。
  7. 运行 npm run build 验证。

最少需要提供的信息

如果要让 Codex 或别人帮你看，至少提供：

信息 说明
目标 你是想本地构建、预览，还是部署
命令 例如 npm run build、hexo generate
关键错误 从 YAMLException 或 FATAL 附近截取
相关文件 出问题的 Markdown 文件路径
Front Matter 只贴顶部元数据，先不要贴整篇文章
最近变更 最近改过哪些文章、页面或配置
限制 是否不想改主题、不想升级依赖、不想部署

也可以直接使用 支持请求格式化器 生成一份结构化文本。

可复制给 Codex 的提示词

什么时候不该继续贴信息

如果 Front Matter 或日志里包含下面内容，先停止并脱敏：

  • 私有仓库地址。
  • 内部域名。
  • 邮箱、手机号、客户名。
  • API key、Token、Cookie、私钥。
  • 订单、支付、身份证件或公司内部资料。
