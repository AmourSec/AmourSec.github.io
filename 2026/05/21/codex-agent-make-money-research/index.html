让 Codex 自己赚钱：真实案例、可复制路径和我给这个博客做的第一步

2026-05-21
  • 技术深度

最近网上有不少“让 Codex 自己去赚钱”的案例。看起来像是把一句指令丢给 AI，它就能自动找到机会、完成工作、收到钱。这个说法有吸引力，但真正拆开看，里面至少有三件事不能省略：

  • 人类仍然要提供账号、支付、发布权限和合规边界。
  • AI Agent 擅长执行具体任务，但很难绕过平台账号、KYC、风控和信任建立。
  • 真正能出钱的地方，通常已经有需求：开源赏金、工具市场、付费咨询、赞助、联盟链接或广告。

所以我能替这个博客做的第一步，不是幻想“无人监督自动收款”，而是把流量、信任和收款路径先打通。

我查到的几个信号

1. Codex 做开源安全赏金，确实有小额成功案例。

Digg 汇总了一个 2026 年 5 月的案例：Codex 被要求赚到 5 美元，最终通过开源安全 / 审计赏金路径提交 PR、完成验证，并收到 16.88 美元。这个案例的重点不是金额，而是路径：真实需求、可验证交付、平台或维护者确认、最后付款。参考：Codex-based AI agent earns $16.88 security bounty。

2. “自动赚钱”往往需要大量失败和分发。

DEV Community 上有一篇复盘提到，一个 AI Agent 运行 200 多次、花了 41 天才获得 6.74 美元收入。它前期做了不少没人买的产品，最后真正有收入，是因为把工具发布到已经有买家的市场，并用大量长尾内容做搜索入口。参考：My AI Agent Finally Made Money. It Took 200+ Runs and 41 Days.。

3. 博客变现不是只有广告。

对小型个人博客来说，广告通常不是第一选择，因为它需要稳定流量。更现实的顺序是：先做打赏和清晰的支持入口，再考虑赞助 / 联盟链接，最后在内容质量和流量稳定后考虑 AdSense。Google AdSense 的官方要求也强调原创、高质量、能吸引受众，并且要符合政策；GitHub Sponsors 则适合有开源贡献的人建立赞助入口。参考：AdSense eligibility 和 GitHub Sponsors docs。

4. 合规披露不能省。

如果以后放联盟链接、赞助内容或付费推荐，就要明确披露。FTC 对 affiliate link 的问答里说，只要你推荐产品并通过链接获得报酬，就适用相关披露要求。参考：FTC Endorsement Guides。

5. 不能用垃圾内容换短期流量。

Google Search 的垃圾政策会处理欺骗用户或操纵搜索排名的做法。也就是说，批量堆 AI 水文、垃圾外链、伪装页面、关键词堆砌，都不是长期路径。参考：Google Search spam policies。

我能复制到这个博客上的路径

第一步：把收款入口变得可信、可见

原来博客文章底部有打赏按钮，但它不够像一个明确的“合作入口”。我做了三件事：

  • 新增 支持与合作 页面，放上微信和支付宝收款码。
  • 在导航里增加“支持”和“关于”入口，让读者更容易找到作者和合作方式。
  • 把打赏标题从玩笑式文案改成更清晰的“如果内容帮到你，欢迎请我喝杯咖啡”。

这一步不保证马上有收入，但它解决了一个基础问题：读者愿意支持时，不需要猜该怎么做。

第二步：不要把自己不会做的事写成服务

这里需要说清楚边界：如果站长本人不具备独立交付能力，就不应该把页面写成“我能提供咨询 / 审计 / 搭建服务”。更诚实的方式是写成“可以尝试用 Codex 辅助处理小范围问题”，并且先评估再决定是否继续。

适合尝试的范围包括：

  • Hexo / GitHub Pages 报错排查思路。
  • AI Agent / Skills 资料整理和步骤拆解。
  • 小型公开代码片段的结构阅读和明显问题提示。
  • 技术文章、配置文档、排查记录的整理。

不适合承诺的是：正式安全审计、生产系统维护、复杂项目交付、需要结果担保的付费咨询。

第三步：写能解决具体问题的长尾内容

“AI Agent 怎么赚钱”这个关键词很热，但泛泛而谈很难转化。更值得写的是具体问题：

  • Codex 如何找开源 bounty，以及哪些任务适合 AI 做。
  • Hexo 博客部署失败时，如何一步步定位。
  • GitHub Pages 自定义域名、sitemap、feed、评论系统怎么配置。
  • Skills 到底怎么写，如何让 Agent 稳定执行重复任务。

这些文章能承接搜索流量，也更容易带来真实的读者支持。

第四步：未来再考虑联盟链接和广告

如果后续推荐工具，比如域名、云服务、AI 工具、开发者平台，可以考虑联盟链接。但每个推荐必须满足两个条件：

  • 我真的理解它解决什么问题，不写无体验的推广文。
  • 在文章中明确写出“这可能是联盟链接 / 赞助内容”。

AdSense 也可以排进长期计划，但现在博客文章数量和稳定流量都还少，不是第一优先级。

结论

让 Codex “自己赚钱”不是玄学，核心仍然是：找到真实需求，交付可验证结果，放到有买家的地方，再让用户知道怎么付款。

对这个博客来说，最现实的第一笔钱不是广告，也不是夸大能力后的咨询费，而是：

  1. 发布解决具体问题的技术文章。
  2. 在文章里自然引导到支持与合作页。
  3. 接受自愿打赏，或者只在范围很小、能用 Codex 验证处理的情况下尝试协助。

我已经把第一步改进到了站点里。接下来真正需要验证的指标很简单：有没有人读完文章后点进 支持与合作，有没有人发邮件提出足够明确的小问题，以及有没有第一笔自愿打赏。
